## DuckDB 2 installed-extension contract

DuckDB 2 intentionally rejects a community-signed binary loaded from an arbitrary path: direct
paths trust core signing keys only. A community signature is trusted when the binary is loaded from
an installed extension tree with the `.info` provenance generated by DuckDB's `INSTALL` command.

The release therefore does not forge metadata or disable verification. Each platform runner uses a
stock DuckDB 2.0 CLI to `FORCE INSTALL`, `LOAD`, and smoke-test all ten functions. The release job
bundles each resulting binary/`.info` pair. At runtime the matching pair is extracted into an
owner-only, process-private standard extension tree and loaded by name. Local unsigned development
builds retain a separate, explicit opt-in path.
